# Anime Vault 运行教程

本文说明 Anime Vault 的安装环境、启动方式、局域网访问、页面使用、番剧资源导入，以及如何将 Anime Vault 接入 Animeko。

Anime Vault 是一个面向个人使用的本地番剧管理和基础观看网页。它可以独立运行，也可以和 Alist、Animeko 组合使用。推荐的组合方式是：Alist 负责挂载网盘，Anime Vault 负责整理海报墙和生成剧集，Animeko 负责搜索、观看和弹幕。

## 环境要求

- Python：3.10 及以上
- 浏览器：Chrome、Edge、Firefox 或 Safari 的较新版本
- 操作系统：Linux、Windows、macOS 或树莓派系统

项目后端只使用 Python 标准库，不需要安装第三方 Python 包。

## 启动 Anime Vault

### 普通启动

进入项目根目录：

```bash
cd ~/Anime
```

启动服务：

```bash
python3 app.py
```

默认监听 `0.0.0.0:8000`：

- 本机访问：`http://127.0.0.1:8000`
- 局域网其他设备访问：`http://运行设备IP:8000`

终端出现类似下面的提示，就表示服务已经启动：

```text
Serving on http://0.0.0.0:8000
```

### 指定端口

如果 8000 端口已经被占用，可以指定其他端口：

```bash
python3 app.py --port 8080
```

其他设备访问：

```text
http://运行设备IP:8080
```

### 只允许本机访问

如果不需要局域网访问，可以绑定到本机地址：

```bash
python3 app.py --host 127.0.0.1 --port 8000
```

### 局域网访问

直接运行 `python3 app.py` 时，服务已经监听 `0.0.0.0`，无需添加额外参数。然后在手机、平板或其他电脑的浏览器中访问：

```text
http://树莓派IP:8000
```

示例：

```text
http://192.0.2.10:8000
```

如果无法打开，请检查运行设备的 IP 地址、防火墙和端口是否正确。

### 只初始化数据库

```bash
python3 app.py --init-db
```

该命令会创建 `data/anime.db`、创建或迁移 `anime` 表和隐私配置表，并写入或更新内置种子资料；它不会启动 Web 服务。

### 首次运行会发生什么

首次启动时，项目会自动：

1. 创建 `data/` 目录。
2. 创建 `data/anime.db`。
3. 创建 `anime`、播放记录和隐私配置相关的数据表。
4. 写入 `anime_vault/seed.py` 中的内置番剧资料。

之后再次启动时，会继续使用同一个数据库，并自动补齐新增字段。内置种子数据会更新基础资料字段，但不会覆盖用户保存的播放地址、剧集配置和播放记录。

## 使用 Animeko 时的启动方式

```
Anime Vault 网页中可以一键复制订阅地址，但是最好检查一下端口和ip是否正确。
```
Animeko 和 Anime Vault 是两个独立的程序。使用 Animeko 时，仍然需要先启动 Anime Vault；Animeko 通过 HTTP 请求 Anime Vault 提供的订阅、搜索和详情接口。

关键区别是：

- Anime Vault 没有设置网页访问密码时，直接运行 `python3 app.py` 即可，Animeko 可以直接读取订阅地址。
- Anime Vault 设置了网页访问密码时，Animeko 不能使用浏览器的密码 Cookie，必须给 Anime Vault 配置一个只读接口令牌。
- `ANIMEKO_API_TOKEN` 必须在启动 Anime Vault 之前设置。服务已经运行后再设置环境变量，不会影响当前进程；修改令牌后也必须重启 Anime Vault。

### Animeko 场景一：未设置网页访问密码

在 Anime Vault 项目根目录运行：

```bash
cd ~/code/Anime
python3 app.py
```

Animeko 中使用以下订阅地址：

```text
http://运行 Anime Vault 的设备IP:8000/animeko/subscription
```

### Animeko 场景二：已设置网页访问密码

先停止已经运行的 Anime Vault，再在同一个终端中设置令牌并启动服务：

```bash
cd ~/Anime
export ANIMEKO_API_TOKEN='请替换为随机长字符串'
python3 app.py
```

也可以使用一行命令启动：

```bash
ANIMEKO_API_TOKEN='请替换为随机长字符串' python3 app.py
```

令牌建议使用随机生成的较长字符串，不要使用访问密码，也不要提交到公开仓库。Animeko 中使用带令牌的订阅地址：

```text
http://运行 Anime Vault 的设备IP:8000/animeko/subscription?token=令牌
```

例如，令牌为 `example-token-123` 时：

```text
http://192.168.0.111:8000/animeko/subscription?token=example-token-123
```

建议将animeko所有的内置订阅备份并删除。
搜索番剧并播放的时候，建议手动选择数据源即Anime Vault的数据源。如果手动选择模式中没有看见Anime Vault的数据源，则需要：

- 复制当前番剧的名字，在Anime Vault网页中重新编辑该番剧的信息，保证animeko中对应番剧的名称和Anime Vault中的一致。

- 检查剧集起始集数是否一致。比如《银魂'》的起始集数其实是`202`，如果Anime Vault的《银魂'》起始集数是`1`,那么animeko就会找不到正确的视频。


```
比如《银魂第二季》在animeko中的名称是《银魂'》,因此在Anime Vault设置的名称也应该是《银魂'》。
```

### Windows 启动方式

PowerShell：

```powershell
$env:ANIMEKO_API_TOKEN="请替换为随机长字符串"
python app.py
```

CMD：

```bat
set ANIMEKO_API_TOKEN=请替换为随机长字符串
python app.py
```

环境变量只对当前终端和从该终端启动的 Anime Vault 进程有效。关闭终端后再次启动，需要重新设置令牌。

### Animeko 连接前检查

在 Animeko 所在设备上确认：

1. 能够访问 Anime Vault 运行设备的 IP 地址。
2. 端口号与 Anime Vault 实际启动端口一致。
3. 如果配置了网页密码，订阅地址中包含正确的 `token`。
4. Anime Vault 进程是在设置 `ANIMEKO_API_TOKEN` 后启动的。

可以先在浏览器中打开订阅地址。如果返回 JSON 文本，并且内容中包含 `exportedMediaSourceDataList`，说明订阅接口可访问。

## 设置网页访问密码

首次进入首页时，点击“添加密码”，输入至少 6 个字符并确认，即可为个人番剧库设置访问密码。项目不需要注册账号。

设置成功后，当前浏览器会话会自动解锁。之后使用新的浏览器会话访问网站时，需要先输入密码；密码正确后才能打开首页、详情页、图片、视频和编辑功能。

进入首页后：

- 点击“修改密码”更换访问密码。
- 点击“锁定”立即结束当前浏览器会话。

密码不会以明文保存，只会将哈希、随机盐和会话签名密钥保存到 `data/anime.db`。迁移项目时如果不复制数据库，密码配置也不会保留。

如果忘记密码，项目没有找回密码流程。请先备份数据库，再删除隐私配置记录：

```bash
python3 -c 'import sqlite3; db=sqlite3.connect("data/anime.db"); db.execute("DELETE FROM privacy_settings"); db.commit(); db.close()'
```

重启服务后，首页会恢复为未设置密码的状态，可以重新点击“添加密码”。这个操作不会删除番剧资料，但原数据库仍应保留备份。

## 首页使用

打开首页后可以看到番剧海报墙和当前馆藏数量。

首页支持：

- 点击海报进入详情页。
- 在搜索框输入标题、题材或关键词即时筛选。
- 点击“新增番剧”打开新增页面。
- 按最近播放活动查看条目顺序。

## 详情页使用

详情页展示海报、横版剧照背景、标题、副标题、发行信息、制作公司、简介、播放地址、剧集演员、关键词、资料来源、剧集列表和上一次播放记录。

点击“返回海报墙”回到首页，点击“编辑资料”进入编辑页面。

## 播放地址和剧集配置

### 播放地址

详情页的播放地址默认是只读状态：

- 点击播放地址输入框时，如果地址非空，会在新标签页打开该地址。
- 点击“编辑地址”后，输入框变为可编辑。
- 修改后点击“保存地址”，地址会写入 SQLite 数据库。

### 剧集 URL 配置

详情页底部有“剧集”面板。点击“配置”后可以编辑：

- `总集数`：控制生成多少个剧集按钮。
- `根域名`：例如 `https://example.com`。
- `路由`：例如 `/watch`。
- `查询参数前缀`：例如 `?ep=`。
- `集数查询偏移`：控制真正拼接到 URL 中的起始编号。
- `其他`：补充额外参数，例如 `&source=anime`。

保存后页面会回到详情页并重新生成剧集按钮。

点击第 `N` 集时，项目按下面的规则拼接 URL：

```text
根域名 + 路由 + 查询参数前缀 + (集数查询偏移 + N - 1) + 其他
```

示例：

```text
总集数 = 25
根域名 = https://example.com
路由 = /watch
查询参数前缀 = ?ep=
集数查询偏移 = 0
其他 = &from=anime
```

点击第 1 集：

```text
https://example.com/watch?ep=0&from=anime
```

点击第 25 集：

```text
https://example.com/watch?ep=24&from=anime
```

点击某一集后，项目会记录该集为“上一次播放”，并在剧集列表中高亮。

## 新增番剧和导入剧集

首页点击“新增番剧”进入新增页面。

所有资源类型都必须填写：

- `slug`：番剧的唯一标识，不能重复。
- `番剧名`

选择“播放链接 / 路由”时还需要提供海报和剧照。选择“M3U8 文件”或“URL 列表转 M3U8”时可以不提供图片，页面会自动使用占位海报。

其他字段可以按需要填写：副标题、发行信息、制作公司、资源、简介、剧集演员、关键词和资料来源。

“资源”提供三种方式：

### 播放链接 / 路由

适合普通视频网站或其他在线播放入口。保留原有的播放地址、总集数和 URL 拼接配置。

### M3U8 文件

上传 UTF-8 编码的 `.m3u8` 播放列表。系统会读取 `#EXTINF` 标题和后续 HTTP/HTTPS 播放地址，并按顺序自动生成剧集。地址中的中文、空格和方括号会在导入时自动编码。

### URL 列表转 M3U8

每行填写一个 HTTP/HTTPS 视频 URL。系统按照 `convert_to_m3u8.py` 的编号规则，使用手工填写的番剧名生成 `#EXTINF` 标题并立即解析为分集；番剧简介、演员、关键词等资料仍需手工填写。

推荐从 Alist 使用此方式：在 Alist 网页中复制每个视频文件的下载链接，按剧集顺序逐行粘贴到“视频 URL 列表”中。

两种导入方式都支持“导入集数显示偏移”。例如填写 `3` 后，播放列表第一条视频的内部序号仍是 1，播放地址和播放进度不会改变，但页面和 Animeko 会显示为“第 4 集”；URL 列表生成的 M3U8 标题也会同步显示为第四集。

选择“URL 列表转 M3U8”后，播放链接、总集数和 URL 查询配置会自动隐藏，只需填写番剧资料、视频 URL 列表和显示偏移。

提交成功后会跳转到新番剧详情页。详情页可以删除已有番剧；删除会同时清理番剧的播放记录，但不会自动删除磁盘上的图片文件。

## 编辑番剧

详情页点击“编辑资料”进入编辑页面。

编辑页和新增页共用同一个表单，但编辑模式下 slug 不允许修改。保存后会更新数据库中的对应条目。

如果重新上传海报或剧照，文件会覆盖同 slug 对应的上传图片文件。

## 本地媒体播放

除在线跳转和 M3U8 资源外，详情页的剧集配置还可以选择“本地页内播放”。配置步骤如下：

1. 打开番剧详情页，展开“剧集 -> 配置”。
2. 将“播放模式”改为“本地页内播放”。
3. 在“本地番剧目录”中填写媒体库内的番剧目录。
4. 保存配置。

系统会按目录中的视频文件顺序生成剧集，并根据目录结构识别季度和来源。浏览器可以在详情页内播放、切换上一集和下一集、调节音量、调整倍速和全屏播放。

本地播放还会保存播放位置、视频时长和完成状态。也可以点击本地播放器中的 `MPV` 链接生成单集 M3U 播放列表。Animeko 使用本地媒体时，Animeko 设备必须能够访问同一个 Anime Vault 服务地址。

## 在 Animeko 中添加 Anime Vault

Anime Vault 提供的是 Animeko 可读取的订阅配置和 Selector 数据源接口，不是对 Animeko 内部数据库的直接导入。订阅接口返回 Animeko 要求的 `exportedMediaSourceDataList` 对象，其中包含 `web-selector` 数据源配置。

### 直接添加订阅

请先按照[“使用 Animeko 时的启动方式”](#使用-animeko-时的启动方式)启动 Anime Vault，并确认 Animeko 设备能够访问运行设备的 IP 地址。

在 Animeko 的“设置 -> 数据源管理 -> 添加订阅”中填写：

未设置网页访问密码时：

```text
http://运行设备IP:8000/animeko/subscription
```

设置了网页访问密码并配置令牌时：

```text
http://运行设备IP:8000/animeko/subscription?token=令牌
```

如果首页显示“一键复制 Animeko 订阅”，也可以直接复制页面提供的地址。Animeko 会自动读取 Selector 配置并定时更新。

### 手动创建 Selector 规则

如果需要手动配置：

1. 在 Animeko 的“设置 -> 数据源管理”中新增 `Selector` 数据源。
2. 未设置密码时，搜索地址填写 `http://运行设备IP:8000/animeko/search?keyword={keyword}`。
3. 设置密码时，搜索地址填写 `http://运行设备IP:8000/animeko/search?token=令牌&keyword={keyword}`。
4. 条目格式选择 `JSON Path Indexed`。
5. `selectLinks` 填写 `$[*]['url','link']`，`selectNames` 填写 `$[*]['title','name']`。
6. 线路格式选择 `No Channel`。
7. 剧集选择器填写 `a.animeko-episode`，名称使用元素文本，链接使用元素的 `href` 属性。
8. 保存后搜索 Anime Vault 中已有番剧，打开详情即可选择剧集播放。

适配接口会为每个剧集输出独立的“第 N 集”文本，保证 Animeko 能识别分集编号。原始 M3U8 标题保存在链接的 `title` 属性中，不会干扰集数解析。

当番剧条目配置为在线路由或 M3U8 时，Animeko 会直接获得对应播放地址；本地媒体模式会获得 Anime Vault 的本地视频接口。

## 图片上传

海报和剧照都支持：

- 手动填写项目内相对路径。
- 点击上传区域选择本地图片。
- 拖拽图片到上传区域。
- 在浏览器内预览图片。

支持格式：

```text
JPG, JPEG, PNG, GIF, WEBP, BMP, SVG, AVIF
```

上传后的海报保存到 `poster/`，上传后的剧照保存到 `Stills/`。

## 数据备份和迁移

最重要的文件是：

```text
data/anime.db
```

它保存番剧资料、播放地址、剧集配置、M3U8 分集、播放记录、播放进度和访问密码配置。如果新增或上传了图片，也要备份 `poster/` 和 `Stills/`。

迁移到新机器时：

1. 停止 Anime Vault。
2. 复制 `data/anime.db`。
3. 如果使用了上传图片，复制 `poster/` 和 `Stills/`。
4. 在新机器上启动 Anime Vault。
5. 如果需要 Animeko 访问，使用新机器的 IP 地址更新订阅 URL，并确保新进程带有正确的 `ANIMEKO_API_TOKEN`。

## 常见问题

### 浏览器无法打开页面

- 确认终端显示了 `Serving on http://...`。
- 确认访问地址和端口正确。
- 如果从其他设备访问，确认没有显式使用 `--host 127.0.0.1`。
- 检查防火墙是否阻止端口。

### Animeko 提示订阅读取失败或 401

- 确认 Anime Vault 正在运行。
- 确认 Animeko 设备可以访问 Anime Vault 的 IP 和端口。
- 如果设置了网页访问密码，确认启动 Anime Vault 前已经设置 `ANIMEKO_API_TOKEN`。
- 确认订阅 URL 中的令牌与环境变量完全一致。
- 修改令牌后，停止并重新启动 Anime Vault。
- 不要把带令牌的订阅 URL 分享到公开位置。

### Animeko 能搜索但无法打开剧集

- 确认 Animeko 使用的订阅地址或搜索地址中包含正确的令牌。
- 确认 Anime Vault 中已经生成剧集。
- 对“播放链接 / 路由”资源，检查总集数、根域名、路由和查询参数拼接规则。
- 对 M3U8 或 URL 列表资源，确认导入后的每条地址都是有效的 HTTP/HTTPS 地址。
- 使用本地媒体模式时，确认 Animeko 设备可以访问 Anime Vault 的本地视频接口。

### 首页要求输入密码

这是正常的隐私保护流程。输入设置时使用的访问密码即可解锁。如果刚刚修改过密码，旧密码和旧浏览器会话都会失效。

### 忘记访问密码

项目不会保存明文密码，也没有账号找回流程。请按照“设置网页访问密码”一节中的命令删除 `privacy_settings` 记录，并先保留数据库备份。

### 图片不显示

- 确认 `poster/` 和 `Stills/` 目录存在。
- 确认数据库中的图片路径是相对项目根目录的路径。
- 确认图片文件名没有被删除或改名。

### 新增番剧提示 slug 已存在

slug 是番剧的唯一标识。换一个未使用过的 slug。

### 点剧集没有正常跳转

- 确认 `总集数` 大于 0。
- 确认 `根域名` 已填写。
- 检查 `路由`、`查询参数前缀`、`集数查询偏移`、`其他` 拼接后是否是目标网站需要的格式。
- 对 M3U8 或 URL 列表资源，确认导入后详情页显示了解析出的剧集和有效的 HTTP/HTTPS 地址。

### 保存后数据没有变化

- 确认表单提交后页面有刷新或跳转。
- 确认 `data/anime.db` 可写。
- 重新启动服务后再检查。

### 需要重置数据库

先备份当前数据库：

```bash
cp data/anime.db data/anime.db.bak
```

如果确定要重新生成数据库，可以删除 `data/anime.db` 后重新启动服务。删除会丢失播放地址、剧集配置、导入的播放列表和播放记录。

## 安全注意事项

这是个人本地工具，不是面向公网的生产服务。

- 默认监听 `0.0.0.0`，同一局域网的设备可以通过运行设备的 IP 地址访问。
- 仅在受信任的局域网中运行；如需限制为本机访问，使用 `--host 127.0.0.1`。
- 访问密码是个人站点级别的保护，不是账号系统，也不提供多用户权限管理。
- 设置密码后，番剧页面和媒体资源需要解锁；用于加载界面的 `static/styles.css` 和 `static/app.js` 仍可公开读取。
- Animeko 只读接口在设置密码后需要 `ANIMEKO_API_TOKEN`。
- 当前服务使用普通 HTTP，不提供 HTTPS 加密。通过不受信任的网络访问时，密码和令牌可能被网络监听。
- 不建议直接暴露到公网。需要远程访问时，建议使用 SSH 隧道、VPN 或带 HTTPS 和认证的反向代理。
