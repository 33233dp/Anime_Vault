# 文本流程图

本文用文本流程图说明 Anime Vault 的主要请求流程和数据流。

## 1. 服务启动流程

```text
执行 python3 app.py
  -> app.py 调用 anime_vault.main
  -> cli.py / parse_args()
  -> repository.ensure_database()
  -> 创建 data/anime.db、anime 表和 privacy_settings 表
  -> 补齐旧数据库缺失字段
  -> 将 seed.py 中的 CATALOG_SEED 写入或更新数据库
  -> create_server(host, port)
  -> ThreadingHTTPServer 启动
```

如果使用 `--init-db`：

```text
执行 python3 app.py --init-db
  -> ensure_database()
  -> 打印数据库路径
  -> 退出，不启动 Web 服务
```

## 2. 访问密码流程

首次访问时：

```text
浏览器访问 /
  -> server.py 检查 privacy_settings
  -> 未设置密码
  -> render_home()
  -> 首页显示“添加密码”
  -> 用户提交 POST /auth/setup
  -> repository.save_access_password()
  -> PBKDF2 哈希密码并生成随机盐、会话签名密钥
  -> SQLite: 写入 privacy_settings
  -> 设置 HttpOnly、SameSite 会话 Cookie
  -> 303 跳回 /
```

已经设置密码时：

```text
浏览器访问任意受保护路由
  -> server.py 校验会话 Cookie 的签名和有效期
  -> Cookie 无效或不存在
  -> 首页显示输入密码页
  -> POST /auth/unlock
  -> repository.verify_access_password()
  -> 密码错误：返回错误提示
  -> 密码正确：签发会话 Cookie 并跳回 /
  -> 后续允许访问详情、媒体资源和编辑接口
```

修改密码会重新生成会话签名密钥，因此旧密码和旧会话都会失效。“锁定”会清除当前会话 Cookie。

## 3. 首页海报墙加载流程

```text
浏览器访问 /
  -> AnimeRequestHandler.do_GET()
  -> handle_dynamic_route()
  -> render_home()
  -> repository.load_catalog()
  -> SQLite: data/anime.db / anime 表
  -> renderers.render_card()
  -> templates/index.html
  -> static/styles.css + static/app.js
  -> 浏览器展示海报墙
```

## 4. 首页即时搜索流程

```text
用户输入搜索词
  -> static/app.js / updateFilter()
  -> 遍历 .poster-card 的 data-search
  -> 根据标题、副标题和关键词匹配
  -> 更新每张卡片 hidden 状态
  -> 更新 #visibleCount
  -> 无结果时显示 #emptyState
```

## 5. 详情页加载流程

```text
用户点击海报卡片
  -> GET /anime/<slug>
  -> AnimeRequestHandler.do_GET()
  -> handle_dynamic_route()
  -> render_detail(slug)
  -> repository.get_anime(slug)
  -> renderers.render_playback_section()
  -> renderers.render_episode_section()
  -> renderers.render_chip_list()
  -> renderers.render_source_list()
  -> templates/detail.html
  -> 浏览器展示详情页
```

## 6. 新增番剧流程

```text
用户点击首页“新增番剧”
  -> GET /anime/new
  -> render_anime_form()
  -> renderers.render_anime_form_page(mode="create")
  -> templates/anime_form.html
  -> 浏览器展示新增表单
```

提交表单：

```text
用户填写基本信息、图片、播放地址和剧集配置
  -> POST /anime/create
  -> create_anime_entry()
  -> read_anime_form_record()
  -> read_request_data()
  -> 如有 multipart/form-data，读取上传文件
  -> resolve_image_path()
  -> save_uploaded_image()
  -> repository.create_anime()
  -> SQLite: 写入 anime 表
  -> 302 跳转到 /anime/<slug>
```

## 7. 编辑番剧流程

```text
用户在详情页点击“编辑资料”
  -> GET /anime/<slug>/edit
  -> render_anime_edit_form(slug)
  -> repository.get_anime(slug)
  -> anime_to_form_values()
  -> render_anime_form_page(mode="edit")
  -> 浏览器展示编辑表单
```

提交编辑：

```text
用户修改资料并提交
  -> POST /anime/<slug>/edit
  -> update_anime_entry(slug)
  -> read_anime_form_record(existing_slug=slug)
  -> 如有新图片，保存到 poster/ 或 Stills/
  -> repository.update_anime(slug, record)
  -> SQLite: 更新 anime 表
  -> 如果总集数变小，会校正 last_played_episode
  -> 302 跳转到 /anime/<slug>
```

## 8. 图片上传流程

```text
用户选择或拖拽图片
  -> static/app.js 检查扩展名
  -> URL.createObjectURL() 生成本地预览
  -> 表单以 multipart/form-data 提交
  -> server.py / read_multipart_form_data()
  -> save_uploaded_image()
  -> 根据 slug 生成文件名
  -> poster/<slug>-poster.<ext> 或 Stills/<slug>-still.<ext>
  -> 数据库保存相对路径
```

## 9. 保存播放地址流程

```text
用户点击“编辑地址”
  -> static/app.js / syncEditingState()
  -> 文本框进入可编辑状态
用户修改后点击“保存地址”
  -> POST /anime/<slug>/playback-url
  -> update_playback_url(slug)
  -> repository.save_playback_url()
  -> SQLite: anime.playback_url
  -> 303 跳回 /anime/<slug>
```

## 10. 保存剧集配置流程

```text
用户点击“配置”
  -> static/app.js / syncConfigState()
  -> 展开 .episodes-config
用户填写配置并保存
  -> POST /anime/<slug>/episodes/config
  -> update_episode_config(slug)
  -> repository.save_episode_config()
  -> SQLite: 保存 episode_count、root_domain、route、query_prefix、start_number、other
  -> 如果总集数为 0 或小于上一次播放集数，则重置 last_played_episode
  -> 303 跳回 /anime/<slug>
```

## 11. 点击剧集播放流程

```text
用户点击“第 N 集”
  -> GET /anime/<slug>/episode/<n>
  -> play_episode(slug, n)
  -> 校验番剧存在
  -> 校验 n 在 1 到 episode_count 之间
  -> renderers.compose_episode_url(anime, n)
  -> mapped = episode_start_number + n - 1
  -> 拼接 root_domain + route + query_prefix + mapped + other
  -> repository.record_last_played_episode(slug, n)
  -> 302 跳转到目标播放地址
```

## 12. 静态文件访问流程

```text
浏览器请求 /static/styles.css、/static/app.js、/poster/...、/Stills/...
  -> AnimeRequestHandler.do_GET()
  -> 认证拦截器先检查会话 Cookie
  -> styles.css 和 app.js 可公开读取，用于渲染认证页
  -> poster、Stills 和其他项目文件需要有效会话
  -> dynamic route 未命中
  -> SimpleHTTPRequestHandler 按 BASE_DIR 提供静态文件
```

注意：设置密码后，认证页面使用的 CSS 和 JavaScript 仍可读取；番剧页面、媒体资源和其他项目文件会先经过认证拦截。服务仍使用普通 HTTP，建议作为本地或受信任局域网个人工具使用。
